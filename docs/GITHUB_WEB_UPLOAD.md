# Publishing INNERnet using GitHub's website (single `main` branch)

Use the **two folders supplied outside the repository**. GitHub's web interface accepts a maximum of 100 files per operation. Do not upload ZIP files directly: GitHub will store them as ZIP attachments rather than extract the repository.

1. Create the empty public repository `shakeelamjid/innernet-protocol`, with **no** autogenerated README, license, or `.gitignore`.
2. Select `Add file > Upload files` (or GitHub's initial upload link) on `main`.
3. Extract the provided combined download. In Finder, open `Batch_01_UPLOAD_CONTENTS_TO_REPO_ROOT`. Press Command+Shift+Period to show hidden files. Select all **contents inside** that folder and drag the files/folders into the upload area. Do not upload the outer `Batch_01...` folder. Commit to `main`.
4. Repeat from `Batch_02_UPLOAD_CONTENTS_TO_REPO_ROOT`, committing directly to `main`. This batch includes `.github/workflows/ci.yml` and `RELEASE_MANIFEST.sha256` so the CI workflow is created after all source files are uploaded.
5. Confirm the root GitHub tree contains `innernet2/`, `tests/`, `docs/`, `deploy/`, `interop/`, `.github/workflows/ci.yml`, `.gitignore`, `.dockerignore`, `LICENSE`, `pyproject.toml`, and `RELEASE_MANIFEST.sha256` without a `Batch_01`/`Batch_02` folder prefix.
6. Open Actions and wait for a green run **on the exact latest `main` commit** for both Python versions, Docker and Go. Do not create the `v1.0.0` tag before these pass. Do not change the live Contabo deployment.
7. On the code page choose Releases > Draft a new release, enter a new tag `v1.0.0` pointing to `main` at that green commit, add the scoped-release notes from `docs/RELEASE_NOTES.md`, and publish.

The release scope covers ST81, OB80-2, R90-ROUTE-1, and UV10-1. Experimental profiles and some security limits are documented in SECURITY.md and docs/STABLE_CORE_SCOPE_AND_LIMITATIONS.md. This is not a professionally audited cryptographic product.
