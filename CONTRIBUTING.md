# Contributing to INNERnet

Contributions to the free protocol, security tests, documentation and interoperability examples are welcome. Open a GitHub issue before proposing major wire format changes; include reproduction steps, expected results and supported versions.

For security vulnerabilities, follow [SECURITY.md](SECURITY.md) rather than opening a public exploit issue. Keep test data synthetic. Preserve independently pinned identity checks and avoid introducing silent legacy fallbacks.

Use a separate branch and pull request. The `INNERnet CI` workflow must pass before merge. Source contributions are provided under the repository's [Apache License 2.0](LICENSE); contributors should confirm they have the rights to submit their code.
